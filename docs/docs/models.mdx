# Model releases

saccade.js turns an eye image into a 128-dimensional embedding with a small ONNX model, and
your calibration turns that embedding into a gaze point. The model is the part that stays
fixed across participants, so it is the part a study needs to be able to name.

Every version below is served from this site at a **versioned URL**. Use it.

## Pin a version

```js
const tracker = new SaccadeTracker({
  assets: {
    modelUrl: "https://saccade.jspsych.org/models/eye-embedding/1.0.0/eye_embedding.onnx",
  },
});
```

There is also an unversioned path, `/models/eye_embedding.onnx`. **Do not use it for data
collection.** It always holds whatever the most recent deploy put there, so a model update
would change your measurements partway through a study — and nothing in your data would
record that it happened. It exists only so older links keep working.

For real studies, [host the model yourself](/guides/hosting-the-assets): download the
versioned file once, serve it from your own origin, and your study cannot be affected by
anything that happens here.

## Recording which model you used

The extension does this for you. When the tracker loads the model it hashes the bytes it
actually received, looks that hash up in the registry that ships with `@saccadejs/core`, and
adds a single `saccade_model` column to your data:

| value                 | meaning                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `eye-embedding@1.0.0` | the loaded bytes hash-matched this published release                                                                            |
| `sha256:f4669a8398d9` | a model that is not a published release, identified by its hash                                                                 |
| `unverified`          | the hash could not be computed (not reachable in a working experiment — the camera needs the same secure context the hash does) |

A version here is not copied from a URL or a filename: it is recorded **because the bytes
matched**. That is why one column is enough, and why a custom model still identifies itself
rather than reading `unknown`.

Only trials that run after the model loads carry it — the camera, and so the model, is not
touched until your first `saccade-preview` trial or your own `start()` call. Trials before
that have no gaze data either.

If you want the full detail — hash, contract, and the URL it came from — ask the tracker:

```js
const id = jsPsych.extensions.saccade.getTracker().getModelIdentity();
// { sha256: "c323131f…", version: "1.0.0", contract: 1, url: "…", resolvedFrom: "registry" }
```

To check a file you downloaded yourself, compare it against the hash in the table below with
`shasum -a 256 eye_embedding.onnx` (macOS/Linux) or
`Get-FileHash eye_embedding.onnx -Algorithm SHA256` (PowerShell).

## How versions are numbered

The model version is **independent of the `@saccadejs/core` package version** — they change
for different reasons, and one does not imply the other.

- **Patch/minor** — new weights, identical interface. Drop-in: the same crop, the same input
  range, the same embedding size. Accuracy may differ; nothing else does.
- **Major** — the preprocessing contract or the model's input/output changed. A library
  version that implements an older contract will refuse to load it rather than produce
  quietly wrong gaze.

The `contract` number in the table is what the library actually checks.

## How long a URL lasts

**Every version listed here stays up.** Once a versioned URL is published we keep serving it,
because by the time anyone asks the question it is already written into a methods section
somewhere. The files are ~20 MB each and sit on GitHub's infrastructure alongside this site,
so there is no pressure to prune them, and the build fails if a published version ever goes
missing.

That is a promise about intent, not a guarantee about the universe. If your study must still
resolve its model in ten years, do not depend on infrastructure you do not control — download
the versioned file, serve it from your own origin, and record the hash. That advice would be
the same for any host.

Models are built and gated in the
[eye-tracking](https://github.com/jspsych/eye-tracking) repository, which trains the network
and exports the ONNX; this repository ships the result.
