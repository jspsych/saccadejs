# The model

SaccadeJS estimates gaze in two stages. First, a neural network looks at a small picture of the
participant's eyes and turns it into a list of numbers describing how the eyes look (an
_embedding_). Then the participant's calibration turns those numbers into a point on the screen.
[How it works](/guides/how-it-works) walks through the whole process.

Calibration differs for every participant, but the network is the same for everyone. It was
trained once and downloads as a single file, which makes it the part of your method to name
precisely in a paper. This page shows you how.

## Releases

Each version above has its own permanent web address, which always serves the same file. Cite
that address in your methods section and point your study at it:

```js
const tracker = new SaccadeTracker({
  assets: {
    modelUrl: "https://saccade.jspsych.org/models/eye-embedding/1.0.0/eye_embedding.onnx",
  },
});
```

For a real study, it is safer still to [host the model yourself](/guides/hosting-the-assets).
Download the versioned file once and serve it from your own server, and nothing that happens to
this site can affect your study.

The table lists a fingerprint (a SHA-256 hash) for each file. To confirm that a file you
downloaded is the published one, compute its fingerprint and compare:

- macOS or Linux: `shasum -a 256 eye_embedding.onnx`
- Windows PowerShell: `Get-FileHash eye_embedding.onnx -Algorithm SHA256`

### What the version numbers mean

The model's version number is separate from the version of the `@saccadejs/core` package. The
two change for different reasons, and a new package version does not mean a new model.

- **A minor or patch release** (for example, 1.0.0 to 1.1.0) is a retrained model with the
  same input and the same outputs. You can swap it in without changing anything
  else. Its accuracy may be different.
- **A major release** (for example, 1.x to 2.0.0) changes how the model is used: how the eye
  picture is prepared, or what goes in and comes out. Adding or removing the frame-quality output
  (`cal_weight`, described below) counts as a major change, because it silently switches every
  calibration between weighted and unweighted.

### How long each version stays available

Every version listed here stays online. Once a versioned address is published, we assume someone
has already written it into a methods section. The files are about 20 MB each and live on GitHub
alongside this site, and the site's build fails if a published version ever goes missing.

Still, we cannot promise the files will be here forever. If your study must be able to find its
model in ten years, keep your own copy. Download the versioned file, serve it yourself, and record
its fingerprint. The same advice applies to a model hosted anywhere else.

The model is trained, tested and exported in a separate repository. This site publishes the
finished files.

## Recording which model you used

The jsPsych extension does this automatically. When the model loads, SaccadeJS computes the
fingerprint of the file it actually downloaded, looks it up in the list of published releases,
and adds a `saccade_model` column to your data:

| Value | What it means |
| --- | --- |
| `eye-embedding@1.0.0` | The file matched this published release exactly. |
| `sha256:f4669a8398d9` | The file is not a published release. The value is the start of its fingerprint, so you can still identify it. |
| `unverified` | The fingerprint could not be computed. Browsers compute it only on secure pages, which the camera requires anyway, so in practice you will not see this. |

SaccadeJS identifies the file by its contents, not its name or URL. It still recognizes a
renamed copy of a published release, and it still identifies a model of your own by its
fingerprint.

The column is set when the model loads, at your first `saccade-preview` trial (or your own call
to `start()`), and jsPsych then adds it to every trial, including the ones that ran before.

For the full details, ask the tracker:

```js
const id = jsPsych.extensions.saccade.getTracker().getModelIdentity();
// {
//   sha256: "5a1a111e…", version: "1.0.0", contract: 1, url: "…",
//   resolvedFrom: "registry",
//   dim: 128,          // how many numbers the model produces per frame
//   emitsWeight: true  // whether it also rates each frame's quality
// }
```

SaccadeJS finds `dim` and `emitsWeight` by running the model once when it loads, rather than
looking them up, so they are correct for an unfamiliar model too.

Whether calibration used the frame-quality ratings depends on the calibration, not the model, so
SaccadeJS records it separately. `saccade-calibrate` saves a `weighting` column with the value
`"model"`, `"head"` or `"uniform"`, and `fitCalibration()` returns the same value.

## Using your own model

If you have trained your own eye model, set `modelUrl` to your model file. It must accept the
same eye picture as the published model, but it can produce any number of values.

**The input must match exactly.** The model receives a 144 × 36 grayscale strip spanning both
eyes, as a float32 tensor of shape `[1, 36, 144, 1]` with values from 0 to 255. SaccadeJS builds
that strip in one fixed way, in this order:

1. crop around fixed MediaPipe face landmarks,
2. convert to grayscale (BT.601),
3. resize with OpenCV-compatible bilinear interpolation,
4. equalize contrast with CLAHE (clip limit 2.0, 8 × 8 tiles).

A model that expects a different shape fails to load, so you will notice. A model that expects
the same shape but was trained on pictures prepared differently will load, run, and produce
nonsense, and SaccadeJS cannot detect that. Check your training preprocessing
against the list above.

**The outputs are flexible.** The first output is the embedding. It can be any length, as long as
it is the same length on every frame of a session. SaccadeJS reads the length from the model.

A second output is optional. If your model has an output named `cal_weight`, `weight` or
`quality`, SaccadeJS reads it as a quality score for each frame between 0 and 1, and uses it to
weight both the averaging of frames and the calibration. An output with any other name is read the
same way if it is the model's only other output and holds a single number. Without one, every
frame counts equally. Live and [deferred mode](/guides/deferred-mode) apply the same rule.

**What SaccadeJS checks.** Two problems stop it when the model loads, before any participant
data is collected:

- an input shape it cannot provide,
- a quality score outside the range 0 to 1 on the warm-up frame.

A third stops it during the session, on the frame where it happens: an embedding whose length
changes from one frame to the next.

SaccadeJS cannot check how your training pictures were prepared. It also does not compare the
`contract` number in the release table with the one it implements. That number is recorded, not
enforced.
